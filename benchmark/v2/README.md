# Benchmark v2

Benchmark v2 contains twelve replay scenarios built from pinned applications, tools, and public background traffic. Each scenario has its own source-derived `ground_truth.json`, evidence logs and manifest, a baseline-relative webroot snapshot, replay metadata, and recording notes. The ground truth uses the v1 schema with additive fields for deleted files, roles, expected-report flags, and vulnerable-code provenance.

No v2 scenario was scored with the `webforensics analyze` or `webforensics eval` commands during recording. Existing benchmark goldens remain unchanged.

The background is 15,000 request rows per scenario from Zenodo Organization X, with NASA client identities paired deterministically. Visitor GET and HEAD requests use paths discovered from the selected app; visitor POST, PUT and PATCH requests use only crawled endpoints that accept those methods. Source scanner request targets remain unchanged; recorded statuses come from the live application. Public request bodies are unavailable and are replayed empty. Round 7 replays the requests live at a source-gap-scaled average of 2–5 requests per second, with no more than 20 background requests in any second. File and log timestamps come from the same uninterrupted recording.

## Restore and score

The committed webroot contains only files created or changed from the pristine baseline. The restore command reconstructs the base tree from public registry-digest-pinned images or SHA-256-pinned source archives, selects the exact manifest bytes from those inputs and the committed overlay, then verifies every manifest entry. The recording's local image ID is provenance only and is not needed for restore:

```powershell
python lab/v2/restore_webroot.py s03 C:\Users\Pongo\Documents\cases\benchmark-v2-restore\s03
```

Choose an empty destination outside the repository. The committed overlay supplies nonsecret installation artifacts that cannot be rebuilt exactly and inert stubs for secret configuration or executable files; `defanged.tsv` records the reason and original hash for each stub. The restore command verifies the manifest hashes and exact file names, including trailing-dot names on Windows. Then score using the existing file-adapter inputs: scenario `evidence/access.log.gz` for `--log`, `evidence/app-error.log` for `--error-log`, `evidence/manifest.tsv` for `--manifest`, the restored directory for `--webroot`, and `evidence/baseline.tsv` for `--baseline`. Use the scenario's `ground_truth.json` as the answer key; do not tune on the held-out split.

Changed executable files, script-containing files, and archive files are replaced in the committed webroot by inert stubs. This includes benign PHP cache or plugin-update files; their original contents remain only in the encrypted full capture outside Git. To score full file content, use `lab/v2/decrypt.py` with the key and external directory configured in the ignored `lab/v2/.env`; follow the isolation and Defender instructions in [`lab/v2/README.md`](../../lab/v2/README.md). Public POST bodies are empty in replay because the source logs contain no bodies.

Each folder stays below 5 MB; the complete `benchmark/v2/` tree stays below 150 MB. The final acceptance checks load evidence and regenerate ground truth but do not run analysis or evaluation.
